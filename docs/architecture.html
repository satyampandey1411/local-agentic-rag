1 · the whole system

Six parts, one GPU

The browser talks to one FastAPI server. Uploads go to a background queue that reads pages on the CPU and indexes them with BGE-M3 on the GPU. Questions go to the agent, which searches the index, reranks, and has Qwen2.5-7B write and check the answer. Watch a PDF go in, then a question.

Click any step below to jump to it.
    2 · once per PDF

    Reading a PDF in two passes, with a save point after every batch

    A 10,000-page PDF cannot be held in memory, and a notebook can disconnect after an hour. So the PDF is streamed: pass 1 reads every page, pass 2 builds the index in page order. Each batch is written to disk before the checkpoint names it, so a crash loses at most one batch. The example is the real 9/11 Commission Report run.

    1. 1
      BROWSER → SERVER

      Upload

      The file streams to disk. The server checks it really is a PDF and within the size limit, then puts it in the queue. You can keep asking about other documents.

    2. 2
      CPU · PASS 1 · 16-PAGE BATCHES

      Read every page

      Worker processes read pages in parallel: reading order across columns, tables rebuilt cell by cell, scanned pages run through Tesseract OCR with the pack chosen from each page's script. A page that crashes or hangs only kills its own worker; it becomes an empty page with a warning.

    3. 3
      CPU · WHILE PASS 1 STREAMS

      Count what repeats

      Lines that repeat in the margins of 40% of pages are running headers, so they are removed. The body font size tells headings apart from text. Both need the whole document, which is why there are two passes.

    4. 4
      GPU · PASS 2 · 48-PAGE BATCHES

      Cut passages and embed them

      Text is cut into passages of at most 320 tokens that never cross a page, so every passage has one page number to cite. BGE-M3 turns each one into a meaning vector, saved to disk as it is made.

    5. 5
      FINAL STEP

      Keyword index

      A BM25 keyword index is built over all passages. The document can already be asked about from the first pass-2 checkpoint; answers say how many pages they came from.

    Sped up about 4×. Grey cells are pages in a batch that is not saved yet; a disconnect throws them away and the run resumes from the last checkpoint. At 10,000 pages the same flow took 37 min on a T4.

    3 · every question

    Find, write, check, cite

    The first scenario is a real question from the recorded demo. The second shows what the agent does when its own check fails. That loop costs extra language-model calls, so it runs only when needed.

    1. 1
      BROWSER · QUEUE

      A question arrives

      Up to two answers run at once. Anyone else waits in a first-come queue and sees their place in it.

    2. 2
      0 TO 2 LLM CALLS · ONLY IF NEEDED

      Prepare the question

      Three checks before searching:

      follow-up → rewrite as a full questionother language → translate to the document'snames a page → pull that page in
    3. 3
      GPU + CPU · 0 LLM CALLS

      Search two ways

      Meaning search (BGE-M3, top 30) finds passages that say the same thing in other words. Keyword search (BM25, top 30) finds exact numbers, names and codes. Reciprocal rank fusion merges both lists by rank and keeps 24.

    4. 4
      GPU · 0 LLM CALLS

      Rerank

      bge-reranker-v2-m3 reads the question and each passage together, which is slower but much sharper than comparing vectors, and keeps the best 6.

    5. +
      ONLY FOR ARITHMETIC · 1 LLM CALL

      Calculator

      The model picks an operation (difference, sum, ratio, percent change, count…) and copies the numbers with their citations. Each number is checked against its cited row and column, then Python does the arithmetic.

    6. 5
      QWEN2.5-7B · 1 LLM CALL · STREAMED

      Write the answer

      The model sees only the 6 numbered passages. It must cite every claim as [n], or reply that the document does not say. Words stream to the browser as they are written. Asked in another language? The answer is written in the book's language, checked, then translated (1 more LLM call).

    7. 6
      QWEN2.5-7B · 1 LLM CALL · JSON

      Check every claim

      Is each sentence supported by the passages it cites? If yes, the answer is done.

    Only if the check fails or the draft refuses · up to 4 more LLM calls
    1. a
      1 LLM CALL · JSON

      Plan sub-questions

      One per item being compared, or per missing fact.

    2. b
      0 LLM CALLS

      Search again

      Passages stay ranked by the original question; each sub-question only adds its best passage.

    3. c
      1 LLM CALL · JSON

      Grade the evidence

      A passage is dropped only if both the grader and the reranker reject it. The order is never changed.

    4. d
      2 LLM CALLS

      Rewrite, then check again

      The rewrite is told which claims were unsupported.

    1. 7
      BROWSER

      Answer with clickable citations

      In your language, or the one picked in the Answer in menu. Each citation opens the source page with the passage highlighted; the sources list names each book. A trace lists every step the agent took.

    Step 1 · a question arrivesLLM calls 0
    Why the loop is not always on. Running plan, search, grade, write and check on every question was measured: on the same 38 questions it got 23 right; a single pass got 27. Sub-question matches crowded out the passage that answered the real question. Now the loop only adds passages, never reorders them, and runs only after a failed check.

    Qwen2.5-7B ties the larger models on accuracy, refuses every question the document cannot answer, and is the fastest of the accurate ones. Gemma-2-9B missed one of the two multilingual no-answer questions. On the 22-language set, Qwen3-8B (93 / 111) and Gemma-3-12B (101 / 111) answered more than Qwen2.5-7B (85 / 111) but refused fewer questions with no answer (8 / 11 and 6 / 11, against 9 / 11).
